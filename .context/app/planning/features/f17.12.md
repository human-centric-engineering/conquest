# F17.12 — the export stops narrowing silently

> §7 of [`f17-followups.md`](./f17-followups.md).

## What was wrong

`loadSessionExport` has built a `notAssessed` list since F17.5, and the PDF never printed it.

That is worse than an omission, because the same export **already filters every listing to what was
in scope**. An area the interview decided not to ask about does not appear as a gap — it does not
appear at all. So an adaptive session's PDF reads exactly like a complete assessment of a shorter
instrument, and nothing in the document distinguishes the two.

The report's method panel does say it. But the panel is a screen, and the PDF is the thing that gets
downloaded, attached to an email, and read six months later by someone who never saw the panel.

## Confirmed decisions

- **Not gated on an `include` switch.** The Q&A listing and the data-slot appendix are appendices an
  author opts into; this is not an appendix. It is the caveat that stops the rest of the document
  being read as something it is not, and an author who could turn it off would eventually turn it
  off.

- **Rendered whatever the report mode.** A woven narrative with no appended Q&A narrows just as
  silently — more so, since the listing that would have shown the gaps is absent. The claim is about
  the interview, not about the listing.

- **After the answer record, before the glossary.** The reader has just seen what was asked; this is
  the sentence that stops them concluding it was everything.

- **Skipped and sampled stay apart**, as they do everywhere else in this feature. "We looked lightly"
  and "we did not look" are different claims about the person holding the document, and one list
  would overstate one and understate the other.

- **Each line carries a question count.** A topic name alone does not tell a reader whether the
  omission matters to them — "Pricing" could be one question or twelve.

- **The wording is a pure function**, `export/not-assessed-view.ts`. The render test file states the
  house rule plainly: react-pdf emits a binary buffer, so content is asserted at the pure-function
  layer. A claim this consequential covered only by a no-throw render test would be untested in
  every way that matters.

## What shipped

| File                                                           | Change                                                                                      |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `lib/app/questionnaire/export/not-assessed-view.ts`            | **New, pure.** `buildNotAssessedView`, `NOT_ASSESSED_NOTE`                                  |
| `lib/app/questionnaire/export/types.ts`                        | `SessionExportModel.notAssessed`                                                            |
| `lib/app/questionnaire/export/build-session-export-model.ts`   | Optional input, defaulting to `[]` so every non-adaptive export is unchanged                |
| `…/questionnaire-sessions/_lib/session-export.ts`              | Passes the list the loader already built onto the model                                     |
| `components/app/questionnaire/export/session-pdf-document.tsx` | `NotAssessedSection` + two styles (muted italic note, sibling of the partial-report caveat) |

**Tests** — new `not-assessed-view.test.ts` (6): empty for a non-adaptive session, the two lists kept
apart, the question count, the `1 question` singular, authored order preserved, and the note itself
saying "never asked … rather than skipped". Plus model-passthrough cases in
`build-session-export-model.test.ts`, a seam case in `session-export.test.ts`, and a render case for
the hardest shape — a narrative deliverable with no Q&A listing, where the note is the only thing
that says the interview was narrowed.

## Not touched

The **transcript export** does not filter by scope — it is the conversation as it happened — so it
has nothing to disclose. The **cohort** exports are a different problem, and a live one: see §6 of
the follow-ups.

# F21.1 — The section model

> Phase A of [the P21 plan](./f21-sectioned-interviews.md). Sections become a thing the product can
> resolve. **Nothing reads them at runtime yet.**

## What shipped

`lib/app/questionnaire/sections/` — pure, client-safe, no Prisma:

| Module        | What it decides                                                               |
| ------------- | ----------------------------------------------------------------------------- |
| `types.ts`    | The vocabulary: `InterviewSection`, the four enums, `MIN_RESOLVED_SECTIONS`   |
| `settings.ts` | `narrowSectionedInterviewSettings` — a malformed blob degrades to feature off |
| `resolve.ts`  | The three-rung ladder, the scope intersection, the ordering rules             |
| `close.ts`    | `assessSectionCompletion` — a section-scoped wrapper over `assessCompletion`  |

Plus the eight-step config path end to end (`sections Json` on `AppQuestionnaireConfig`, the
settings registry entry, the config route's merge patch, the Settings-tab UI, `copyVersionGraph`).

## The decisions worth keeping

**Sections are resolved from groupings that already exist, never a fourth model.** Topics win where
they are live, because a topic already carries BOTH question and data-slot membership, an ordinal
and a respondent-facing label — and because `resolveScope` already returns the membership maps at
full scope, with the feature off. Themes are the common fallback; document sections are the last
rung, and the weakest, because data slots routinely cross a document section boundary.

**An explicit pin is honoured only when that grouping can actually supply sections**, then falls
through to the ladder. An author who pinned `topics` and later switched Conditional Topics off gets
a working sectioned interview rather than an unsectioned one that silently ignores the rest of their
settings.

**The close gate wraps `assessCompletion` rather than restating it**, so the gate ordering, the
`answerConfidenceFloor` filtering and the `COVERAGE_EPSILON` guard cannot drift from the
version-level gate they are the section-scale twin of.

**A one-section interview is deliberately NOT sectioned.** The resolver returns the empty list
rather than the single section, so every caller falls back by construction instead of by remembering
a length check. One section is the whole questionnaire with a tab strip above it and a "move on"
control that goes nowhere, which is strictly worse than the unsectioned surface.

## Two defects the tests caught while being written

1. **Neutralising the wrapped cap with `0` is not "off".** `assessCompletion` reads
   `cap !== null && answered >= cap`, so zero fires on the first assessment — and every section was
   reported closeable before a word had been said.
2. **The two close bars are ANDed, not ORed.** They are the twins of `coverageThreshold` +
   `minQuestionsAnswered`, not of the early-finish pair — whose OR is right for a respondent's right
   to leave and wrong for an author's statement about when a section is covered. The copy said OR in
   four places and was wrong in all four.

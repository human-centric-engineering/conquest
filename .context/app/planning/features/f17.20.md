# F17.20 — Turn a gap into a topic

> The one open item both `f17.19.md` and `f17-followups.md` name after F17.19 shipped: "Gaps are
> shown but not actioned — there is no 'turn this gap into a topic' shortcut."

## What was wrong

F17.19 built the whole arc except its last step. Phase 1 detects a document is worth routing; Phase
2 makes the analyst admit what it recognized but couldn't formalize into a topic or rule (`gaps[]`);
Phase 3 runs the analyst automatically so a draft is waiting; Phase 4 puts the routing design in a
stakeholder-facing export. But a gap itself was — and still is — pure text. An admin reading
"Recognized but not formalized: 'use judgement for respondents outside these categories' — too vague
to test mechanically" had no path from that sentence to a topic except closing the analyst card,
scrolling to the topic list, clicking "Add topic", and re-typing what they had just read.

## What shipped

A "Turn into topic" button on each gap in `RoutingAnalystCard`. Clicking it asks `TopicsPanel` to
seed a new draft row in `TopicListEditor`, filled from the gap:

- `criteria` ← the gap's `sourceQuote` — the document's own words describing the condition, which is
  a far better starting point than the analyst's meta-commentary about why it couldn't formalize it.
- `description` ← the gap's `explanation` — kept as a note for whoever finishes authoring the row
  (often naming what's missing, e.g. "no data slot captures headcount"), not as the condition itself.
- `label` empty, `phase: 'conditional'`, no members. The admin still names it, picks its questions
  and data slots, and reviews the wording — this shortcut removes the re-typing, not the judgment.

The row is expanded and scrolled into view, same as the routing map's existing "Edit this topic".

## Confirmed decisions

- **Reused the `focusTopic` handoff shape rather than inventing a new one.** `topics-panel.tsx`
  already carries a nonced `{ key, nonce }` request from the routing map to the topic editor for
  exactly this reason — asking for the same thing twice must still act, which a bare value can't
  express (unchanged state, effect never re-fires). `seedTopic` is `{ description, criteria, nonce }`
  on the same pattern: two gaps producing identical text must still each add their own row.

- **Purely local — no new save path.** Seeding a row is a `setDrafts` call inside
  `TopicListEditor`'s existing draft state, the same one "Add topic" already mutates. It writes
  nothing until the admin presses "Save topics"; discarding the analyst's proposal (or navigating
  away without saving) discards the seeded row with it. No new endpoint, no new mutation.

- **`criteria` from the quote, `description` from the explanation — not the reverse.** The analysis
  prompt's own rubric is explicit that `explanation` is meta-commentary ("what you recognized, and
  specifically why you could not turn it into a topic or rule"), not a condition — putting it in
  `criteria` would seed a field the routing agent judges respondents against with a sentence like
  "no data slot captures headcount," which reads as nonsense to whoever the agent is actually
  evaluating. `sourceQuote` is the document's own eligibility language, which is what `criteria`
  already is everywhere else in this feature (topics, rules).

- **No confirmation, no undo beyond "remove the row".** Unlike accepting the analyst's proposal
  (which replaces the live topic set and forks a launched version), this only appends to an
  in-progress draft the admin has not saved — the same blast radius as clicking "Add topic," which
  has none either.

## What changed

| Path                                             | Change                                                                                    |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `components/.../topics/routing-analyst-card.tsx` | `onTurnGapIntoTopic` prop; "Turn into topic" button per gap                               |
| `components/.../topics/topic-list-editor.tsx`    | `seedTopic` / `onSeedHandled` props; the seeding effect (mirrors the `focusTopic` effect) |
| `components/.../topics/topics-panel.tsx`         | Wires the gap's `sourceQuote`/`explanation` into `seedTopic`, nonced                      |

No migration, no new endpoint, no new setting.

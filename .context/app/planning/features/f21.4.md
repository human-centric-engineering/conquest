# F21.4 — The artefacts

> Phase D of [the P21 plan](./f21-sectioned-interviews.md). A sectioned interview was experienced in
> parts, and until this shipped nothing it left behind said so.

## What shipped

| Artefact           | Change                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| Transcript (txt)   | Section headings, via the shared `withSectionHeadings` rule                                                |
| Transcript (PDF)   | The same headings, from the same rule                                                                      |
| Transcript (copy)  | Free — it rides the text endpoint                                                                          |
| Respondent report  | `report/chapters.ts`: the answer transcript and the data-slot context bucketed by part, plus a shape block |
| Admin session view | `SectionTimelineCard`: opened, finished, came-back-to, turns spent, spend per section                      |

## The heading rule is not a group-by

A heading is emitted whenever a line's label differs from the last one **printed**. Under `free`
navigation a respondent may work in part one, move to part three and come back — two genuine visits,
minutes apart. A grouping would merge them into one block and misreport when things were said. The
heading repeats because the visit repeated.

The rule lives in one module read by both renderers, so a download taken in either format divides the
conversation identically. An unlabelled line emits nothing and does not clear the tracker, so a
session that turned sections on part-way through does not re-announce the section its early turns
interrupted.

## A part never reached is a THIRD kind of gap

The writer already holds two, and the prompt now states all three together because that is the only
way to keep them apart:

| Gap                    | What it means                                             | What it licenses                       |
| ---------------------- | --------------------------------------------------------- | -------------------------------------- |
| Question **skipped**   | It was put to them and they declined                      | "You may want to come back to this"    |
| Topic **excluded**     | Conditional Topics judged it not to apply, and said so    | Nothing — do not suggest completing it |
| Part **never reached** | It applied, was offered, and the interview stopped before | "This was not covered" and returning   |

Left unstated, a report over a half-finished sectioned interview reads as a complete assessment of a
smaller instrument.

**Reached but unfinished counts as covered.** The respondent was there and their answers are in hand,
so a thin chapter is the honest result; an absent one would claim the interview never went near it.

## Chapters are emitted in CHAPTER order, not answer order

Free navigation lets a respondent answer part three before part one, and `capture` tangents produce
out-of-order fills even under `sequential`. A report following the panel's order would present the
interview in an order nobody experienced.

The writer is asked to follow the parts and **explicitly licensed to merge two or drop one** it has
nothing to say about. A chapter written to fill a heading is worse than no chapter.

## The gate: never pay to be told the feature is off

Resolving a session's sections after the fact goes through `buildTurnContext`, which is not cheap.
The first build paid that on EVERY report generation and EVERY admin session view — the same defect
phase C found on the respondent strip. Both callers now gate on `sectionRun`, read from a row they
were already loading and null on every unsectioned session.

The report's 77 existing tests then passed untouched, which is the proof that an unsectioned
session's prompt is byte-identical to what it was before P21.

## The timeline reads two different sources on purpose

- **Turns** come from the run's counted `turnsSpent`, because that is what `maxTurnsPerSection`
  measures against and therefore the number that explains why a capped section released when it did.
- **Spend** comes from the turn rows, because the run has no notion of cost. A section whose turns
  predate cost capture reads as **unknown**, not zero: "we did not record it" and "it was free" are
  different claims.

A section the version no longer carries is shown, marked stale, for the same reason the reconciler
keeps its entry — turns were tagged with it, and hiding the row would leave them belonging to nothing
while the timeline claimed to account for the whole run.

## Two things deliberately not built

- **The raw answer appendix keeps the panel's own grouping.** That is what the respondent saw in the
  panel, and regrouping it would mean carrying the chapter list on the stored report row and through
  the PDF. The AI chapters above it already follow the run.
- **The run-level (journey) report keeps its per-leg headings.** A run spans several legs, each
  possibly sectioned differently or not at all; merging their chapter lists would collide keys and
  impose an order no respondent experienced.

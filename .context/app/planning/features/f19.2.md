# F19.2 — Six typeface pairings, one of them monospace

> The brand kit shipped with three pairings. Three covered three voices and left the two most-asked
> -for brands with nothing to pick.

## What was wrong

`FONT_PAIRINGS` held `neutral`, `editorial` and `contemporary` — a system sans, a printed-matter
serif, and a technical grotesque. The setting exists so a prospect can tell their questionnaire
apart from the last one, and for a large middle band of brands it could not: the warm, human,
approachable one had to take Contemporary (which sounds engineered) or Neutral (which sounds like
nothing), and the fixed-width engineering one had no option at all.

Nothing was broken. The dial was just too short to do the job it was added for.

## What shipped

**Three more pairings**, each a distinct voice and no two sharing a face:

| Pairing     | Display / Body                 | Voice                                       |
| ----------- | ------------------------------ | ------------------------------------------- |
| `humanist`  | Outfit / Source Sans 3         | warm and open — the safest step off Neutral |
| `classical` | Playfair Display / Lora        | formal, high-contrast, established          |
| `monospace` | JetBrains Mono / IBM Plex Mono | terminal, typewriter, engineering           |

**`MONO_FONT_STACK`**, new and load-bearing. Both mono stacks tail it rather than
`NEUTRAL_FONT_STACK`. That is the one place in this module where the generic actually matters: a
mono questionnaire whose webfont has not arrived falls back to the neutral sans, renders
proportional, and then **reflows to fixed-width mid-read** the instant the face lands. Ending in the
`monospace` keyword makes the swap fixed-width → fixed-width, which barely moves.

**Six more `next/font` declarations in `app/layout.tsx`**, all `preload: false` like the four before
them, so no marketing page fetches type only a demo client uses.

## Confirmed decisions

- **Monospace is a whole pairing, not a flag beside the dial.** A questionnaire set in mono is a
  brand voice, not a rendering mode. Keeping it on the same dial means every option has the same
  shape — two faces plus a generic tail — and the picker stays one question rather than a question
  plus an exception.
- **The admin copy states the cost.** Mono body text reads slower once answers run long, and the
  description line says so. The picker's job is to let a client choose, not to hide the trade.
- **The parity test now DERIVES its face count** — `(FONT_PAIRINGS.length - 1) * 2` — rather than
  asserting `4`. The hardcoded number would have had to be edited by hand by exactly the person
  adding a pairing, which is the person least likely to notice they had also skipped the
  `preload` opt-out. That opt-out is what makes the list cheap to grow, so the test guarding it
  must grow with the list on its own.
- **Two further invariants pinned in the same file.** No two pairings may share a `--font-brand-*`
  variable (a duplicate costs a download to look identical on screen, making one of the two
  options a lie), and `monospace` must tail the fixed-width generic.
- **No migration.** `fontPairing` is already plain TEXT, `resolveFontPairing` is already forgiving
  on read, and the Zod write boundary derives its enum from `FONT_PAIRINGS` — so the column, the
  form, the preview and the settings table all widened from the one edit.
- **IBM Plex Mono names its weights.** It has no variable axis on Google Fonts, so `400`/`500`/`600`
  are declared: body copy, the emphasis Markdown produces inside an answer, and the semibold the
  strip and buttons reach for. It is the second static face in the set — Instrument Serif is static
  too, but ships a single weight, so it names that one and has no range to choose from.

## Still open

- **Nothing renders the pairings side by side.** `DemoClientThemePreview` does set its sample in the
  chosen faces — it spreads `themeToCssVariables` and reads `--app-font-display` / `--app-font-body`
  — so the admin sees the pairing they picked. What they cannot see is the other five without
  clicking through them one at a time. Six options is around the point where a specimen strip
  starts to earn its place.
- **The `<select>` option labels carry no type.** The one-line description under the control does
  the explaining, and the preview does the showing, but the dropdown itself is six words in the
  admin's own font — so the first choice is made blind and corrected by preview.

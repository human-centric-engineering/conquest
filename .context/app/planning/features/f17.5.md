# F17.5 — Report and scoring awareness

> F17.2 made the runtime honour the plan. This makes everything downstream of a completed session
> say what the plan left out — because a narrowed interview that reads like a full assessment is the
> single failure mode this whole phase has to avoid.

## The three claims that must never be blurred

An adaptive instrument produces three different statements about a respondent, and every surface
here exists to keep them apart:

1. **"They were asked and did not answer."** A gap. Inviting them back to it is helpful.
2. **"They were never asked."** Not a gap — a decision, which they were told about. Recommending they
   go and complete it contradicts what the interview said to them and makes the adaptation read as a
   malfunction.
3. **"We looked lightly."** The blind-spot check. There _is_ information; it is a signal, not a
   measurement, and presenting it with the confidence of a scored area overstates the instrument.

## Confirmed decisions

- **The report's scope block is separate from its coverage block**, and sits immediately after it.
  Collapsing the two would be a lie in both directions: it would imply a respondent declined things
  they were never shown, and it would hide that the instrument narrowed itself. Read side by side is
  the only way the writer keeps them apart.

- **The method record carries the topics, not just a count.** "How this report was created" is where
  a reader goes to find out what it is based on; a method panel that omitted the narrowing would be
  the last place it could have been caught. The topics are **named**, because "three areas were not
  covered" leaves a reader unable to tell whether the one they care about was among them.

- **The deterministic summary template states it too.** The template is what a reader gets whenever
  the explainer agent is off or failed, so the narrowing cannot be something only the AI-written
  summary mentions.

- **`allowedNumbers` admits the two scope counts.** Without that, the honesty check would reject the
  one sentence that tells a reader the assessment was narrowed — the summariser would be silently
  forbidden from being honest.

- **The summariser gets counts, never labels.** Topic names are author prose, and the digest already
  withholds document names and search queries for the same reason: untrusted strings in a prompt
  whose output is shown to a respondent as a statement about our own system. The panel renders the
  names itself, from the record.

- **Scoring gains counts, not arithmetic.** `assessedItemCount` / `totalItemCount` on `ScaleScore`
  change nothing about a computed score — an out-of-scope item had no answer either way. What they
  change is the record. `isPartiallyAssessed()` lives beside the type rather than being re-derived at
  each surface, because **a band from three of eight items is not the same measurement as one from all
  eight**, and a cohort chart that puts them in the same column is comparing two instruments while
  looking like it is not.

- **Both count fields are optional.** A score row written before P17 narrows cleanly, and absent
  reads as "everything was asked" — which is exactly what was true then.

- **`scoreSessions` resolves settings once per version, scope once per session.** The plan is per
  respondent so scope must be, but a cohort of hundreds on one instrument should not re-narrow the
  same settings blob each time. A session with no plan on an _enabled_ version passes its null plan
  through rather than being special-cased to full scope — that is the pre-planner state, where only
  the always-run phases ran.

- **The interview plan renders above the transcript**, not below it. A conversation that never
  touched an area reads as an oversight until you know it was a decision, so the plan is the frame
  the transcript has to be read in. What was **not** covered gets equal space: a challenge to a
  report is nearly always about something the interview did not ask.

- **"Nothing — the plan was not announced" is stated, not hidden.** An unannounced plan is a
  respondent who never got the chance to object to it, which is exactly what a later challenge turns
  on.

## Follow-ups

- **The cohort report does not yet surface partial assessment.** `isPartiallyAssessed` exists and the
  counts are persisted, but no chart or segment table reads them. Until it does, a cohort chart can
  still put a three-item band and an eight-item band in the same column.
- **The PDF export's appendix is narrowed but unlabelled.** `loadSessionExport` already filters the
  sections, so an unasked question does not appear — but the export does not yet print the
  `notAssessed` list, so a reader cannot tell a short instrument from a narrowed one.

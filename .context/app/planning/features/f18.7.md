# F18.7 — Interviewer-policy analytics

## What was wrong

Every interviewer-policy surface described **intent**: the rules you wrote, the arc you chose, the
fidelity you set. None described what happened when real respondents met them.

Conditional Topics had exactly this and it was judged worth building (`analytics/routing.ts`, F17.16),
for a reason that transfers wholesale: the failures that matter most are invisible by nature. An arc
that never narrows produces no error and no empty state. A `must_ask` question no plan ever reaches
looks, from every authoring surface, exactly like one that gets asked in every interview.

There was also a data gap underneath it. `funnelPhase()` is a pure function of coverage — but
coverage was computed live per turn and never persisted, so the question "did the arc ever actually
narrow?" had no answer at any scale.

## What shipped

**Two denormalised columns** on `AppQuestionnaireTurn` — `funnelPhase` and `coverage` — written by
`persistTurn` alongside the existing `durationMs` / `promptTokens` / `completionTokens` rollup, and
for exactly the same reason: the Diagnostics precedent of aggregating over columns rather than
parsing the per-call JSON blob.

**`lib/app/questionnaire/analytics/interviewer-policy.ts`**, structured like `routing.ts` — a pure
`assembleInterviewerPolicyAnalytics` over already-loaded rows, and a thin `getInterviewerPolicyAnalytics`
that is the only part touching Prisma.

**A fourth tab** on the analytics page, named "Interviewer".

## Confirmed decisions

- **The phase is recorded from the same helper the phraser uses.** `funnelPhase(ctx,
paceProfile(settings))`, at the same point in the turn, so the recorded phase is the one the
  interviewer actually behaved as — never a re-derivation that could drift from it.
- **Coverage is computed unconditionally**, not only when the strategy is enabled. It is cheap, and
  gating the write would make a null ambiguous between "the arc was off for this session" and "this
  turn predates the column".
- **The arc is counted per SESSION, by the furthest phase reached.** Counting turns would weight a
  twenty-turn interview more heavily than a five-turn one that got just as far. "Furthest" also has
  to mean furthest rather than last: a terse answer steps the phase toward targeted and a rich one
  steps it back, so the sequence is not monotonic. Both are pinned by tests.
- **A turn with no recorded phase is reported, never folded into `open`.** `turnsWithoutPhase` is on
  the result and the panel prints it. Treating unknown as broad would invent a narrative out of
  missing data — the same class of error as reading a null cost as zero.
- **Findings are observations, not verdicts**, with their sample size in the message, silent below
  `POLICY_FINDING_MIN_SESSIONS` (5). A deliberately separate constant from `K_ANONYMITY_THRESHOLD`
  and from `ROUTING_FINDING_MIN_PLANS` despite sharing the value: one governs disclosure, these
  govern inference, and sharing would let a privacy change silently redefine what counts as
  evidence.
- **`arc_never_narrowed` only fires when a funnel is actually configured.** An `open` approach is
  _supposed_ to stay open; reporting that as a failure would be the surface arguing with a correct
  decision. Same guard the routing findings apply to conditional-only topics.
- **House rules are reported as a CONFIGURATION count, and the panel says so on the card.** There is
  no per-turn record of a rule firing. Every turn's full prompt _is_ saved, so a rule's presence can
  be confirmed for any single interview from the Turn Inspector — but counting how often one changed
  an answer means inferring intent from prose. A number with no basis is worse than none, so the
  panel states the limit instead of implying a count.
- **`inspectorCalls` is still never read in aggregate**, anywhere in this layer. That rule is what
  keeps the analytics layer able to use SQL aggregates.
- **k-anonymity suppression zeroes everything except `sessions`** — the same carve-out
  `getRoutingAnalytics` makes, so the surface can say how far off the threshold it is.
- **The tab is called "Interviewer", not anything with "funnel" in it.** `analytics/funnel.ts` is
  the completion funnel (invited → completed) and is unrelated; both docblocks now say so.

## Still open

- **Nothing measures whether a must-ask question was put _as written_.** `cardShown` is the closest
  the schema comes, and it is a proxy: the card is emitted for a typed must-ask, so a `free_text`
  one correctly reaches without one. Judging the wording is a job for the policy judge panel, not a
  counter.
- **The opening-probe allowance is not reported.** It is derivable from the turn record the way
  Conditional Topics already derives `spent`, but it needs the opening-topic join and was cut to keep
  this phase to one migration.

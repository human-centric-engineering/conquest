## What the smoke proves that the unit tests cannot

24 assertions against a real Postgres, end to end through the real loaders. The valuable ones are
**negative**, because "inert when off" is a claim about what the real loaders do with a real row,
and no hand-built fixture can check it:

- with no settings written, `buildTurnContext` reports the interview unsectioned **and carries no
  section pools at all**, so targeting sees exactly what it always saw;
- a version resolving to ONE section runs unsectioned, not as a single-tab interview;
- switching the feature off **unsections a session that already banked a run**, and the admin
  timeline disappears with it. The setting is the switch; the blob is only a record.

The positive half walks the whole chain on one scratch questionnaire: two sections resolve in
document order, the section pool is 2 of 4 while the measured list stays 4, the close gate refuses an
untouched section, the transcript resolves the stored key to the section TITLE and never leaks the
key, the report resolves a covered part and an unreached one, and the timeline sums spend from the
turn rows while reading a never-opened part as unknown rather than free.

Run it against a throwaway database, not the dev one:

```bash
createdb conquest_smoke
sed 's#/conquest"#/conquest_smoke"#' .env.local > /tmp/.env.smoke
npx dotenv-cli -e /tmp/.env.smoke -- npx prisma migrate deploy
npx tsx --env-file=/tmp/.env.smoke scripts/smoke/sectioned-interview.ts
```

## One naming decision to revisit

The script is registered as `smoke:sections`, matching the existing `smoke:scope`
(`conditional-topics.ts`, also ConQuest-owned). `scripts/smoke/README.md` reserves `smoke:*` as a
Sunrise namespace and asks forks to use `app:smoke:*`. The local precedent was followed for
consistency and discoverability; the cost is a `package.json` conflict on upstream sync, which that
file has on every sync anyway. Worth settling for both scripts at once rather than for one.

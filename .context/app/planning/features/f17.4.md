# F17.4 — The Routing Analyst

> The Topics surface can be authored by hand. This is the reason it usually will not have to be:
> most real instruments already say which parts apply to whom, in a place structure extraction
> throws away.

## The gap this closes

Structure extraction reads an uploaded document for its **questions**. Everything else is discarded
— which is correct for extraction, and is precisely the problem here, because the pages it discards
are where an author states their routing: "Routing", "Guardrails", "Scoring notes", "How to use this
assessment", facilitator instructions, eligibility notes.

The pilot client workbook is the canonical case. Its Read Me tab holds the cascade algorithm in prose, its
Routing tab holds twelve signal→section rules with priorities, its Guardrails tab holds six
constraints. None of that survives extraction. The analyst is the second reader that goes back for
it.

## Confirmed decisions

- **A proposer, never an author.** Everything lands in `AppQuestionnaireTopicDraft` — the same
  not-live contract as `AppDataSlotDraft` and the glossary's `proposed` terms. The runtime scope
  resolver, the planner and the launch gate read only `AppQuestionnaireTopic`.

- **The analysis route does not fork a launched version; the accept does.** A proposal is inert —
  nothing but the review surface reads the draft table — so writing one to a launched version changes
  nothing a respondent can see. That is the same split the glossary's analyse-vs-save routes draw.

- **Grounding is the deliverable, not the taxonomy.** A model asked "what are the topics?" will
  confidently invent a clean set from the section headings, and that answer is worse than useless: it
  _looks authored_, so an admin accepts it, and the instrument then routes on the model's invention
  rather than the author's rule. So the contract forces the analyst to declare which it did —
  `sourceQuote` per item, **absent entirely** when inferred, and `fromDocument` on the whole set. The
  review surface renders a visibly different banner for each.

- **`maxConditionalTopics` is reported only when the document states one.** The pilot cap of three
  is derived from a 600-second budget, not chosen; if the document says nothing about breadth, a
  default here would put the analyst's guess where the author's silence was.

- **A conditional topic with no criteria is refused at the contract**, not accepted into the review
  queue. It would give the planner nothing to judge and the admin nothing to correct — it is not a
  proposal, it is unfinished work handed back.

- **`replacesExisting` and the uncovered-question count are computed server-side.** Both are facts
  about the database. A model asked to self-report them would sometimes be wrong about the one number
  the reviewer uses to decide whether to accept.

- **Rules travel with the topics in one proposal.** The analyst reads a document's routing
  instructions as one piece of prose — "ask about pricing only for companies over 50 staff, and never
  score enterprise accounts on self-serve onboarding" — and splitting that across two review surfaces
  would make each half un-reviewable on its own.

- **Accept replaces rather than merges**, and never touches `enabled`. Accepting a proposal is an
  authoring act; turning the feature on is a decision about what respondents are asked, and stays the
  admin's explicit choice.

- **The accept clears the source version's draft after a fork.** `copyVersionGraph` deliberately does
  not carry a draft into a fork, so without this the source keeps a review queue for work already
  done, and re-accepting would write the same topics twice.

## Follow-ups

- The analyst reads the **newest** source document only. An instrument delivered as several files
  (a question bank plus a separate routing memo) needs either a re-ingest that merges them or a
  multi-document input.
- Nothing yet replays a recorded analysis against a changed prompt. The `AppAiRun` snapshot holds the
  output but not the resolved prompt text, so a rubric change cannot be diffed against past runs.

# F17.27 — Plain English on the Adaptive Scope tab

Phase 4 of the tab simplification. A rename pass already landed (`seated` → _included_, `vetoes` →
_blocks_, `the cap` → _the limit_), but internal agent names and code words survived on screen.

## The rule this follows

`adaptive-scope.md` already records it: **the test is not whether a word is technical, it is
whether the product ever teaches it.** `Light depth` is a labelled control on the topic editor, so
it stays; `Routing Analyst` was never anywhere but the source and a docblock, so it goes.

Domain words deliberately untouched: **topic**, **data slot**, **opening**, **conditional**,
**hard rule**, **guardrails**, **blind-spot check**, **Full / Light depth**.

## What changed on screen

| Was                              | Is                                             |
| -------------------------------- | ---------------------------------------------- |
| Routing Analyst                  | **Suggest topics from your document**          |
| Routing map (button + dialog)    | **Decision flow**                              |
| What routing actually did        | **What happened in real interviews**           |
| Scope evaluation                 | **AI review of this setup**                    |
| Scope evaluations (sub-pages)    | **Past reviews**                               |
| Run the planner / Planning…      | **Preview the decision** / **Working it out…** |

| Session length budget            | **How long an interview may take**             |
| Confidence needed                | **How sure the AI must be**                    |

ⓘ popover titles that carried the code's word while the field beside them already read plainly:
`Phase` → **When it runs** · `Depth` → **How much of it** · `Criteria` → **When this applies** ·
`Fallback topics` → **Ask these instead** · `Confidence floor` → **How sure the AI must be** ·
`Planner instructions` → **Extra guidance** · `Topic limit` → **How many topics** ·
`Blind-spot preference` → **Which topic to sample** · `What a gap means` → **Things it could not
turn into a topic** · `Steering the analyst` → **Steering the suggestions**.

**Decision flow**, not the "How the choice is made" the preview suggested: that collides with the
settings card's existing (and good) "The decision, in order".

## The vocabulary fix worth making deliberately

The settings said "Most **conditional** topics per interview" while the phase chip said "Ask when
it fits" — the same concept under two names, which is a large part of why the page read as unclear.

`conditional` is the word the product teaches everywhere else (the docs, the issue messages, the
report vocabulary), so **the chip agrees with it** rather than the reverse: the badge now reads
**Conditional**, and the phase _selector_ keeps the gloss as "Conditional — ask when it fits",
because the selector is where the word is taught.

Renaming `conditional` to "optional" was considered and rejected — it would desync from the docs,
the issue messages and the report vocabulary all at once.

A side effect worth noting: the filter chip and the phase badge now both read "Conditional", which
made one test's `getByRole('button', { name: /Conditional/ })` ambiguous. That ambiguity **is the
fix working** — the filter and the thing it filters finally use one word — so the test now
disambiguates on `aria-pressed` rather than the copy reverting.

## What was NOT renamed

Agent slugs, capability names, `AppAiRun` kinds, component filenames and docblock prose. They are
not on screen, and renaming them would churn the code and the trackers for no reader's benefit.
